# VS Code для работы с LaTeX

Эта заметка описывает настройку Visual Studio Code для работы с LaTeX: отдельный профиль, LaTeX Workshop, автоматическую сборку, перенос длинных строк при отображении, встроенный PDF viewer и SyncTeX.

## 1. Что должно быть установлено

Нужны три независимых компонента:

1. **Visual Studio Code** — редактор.
2. **LaTeX-дистрибутив** — компиляторы и пакеты LaTeX.
3. **LaTeX Workshop** — расширение VS Code, связывающее редактор с LaTeX-инструментами.

VS Code и LaTeX Workshop сами по себе LaTeX не компилируют. В системе должен быть установлен отдельный LaTeX-дистрибутив.

Для Windows обычно используются:

* MiKTeX;
* TeX Live.

Если MiKTeX уже используется для работы с LaTeX, менять его ради VS Code не требуется.

---

## 2. Создание отдельного профиля LaTeX

Для LaTeX удобно создать отдельный профиль VS Code.

Открыть:

```text
File → Preferences → Profiles
```

или меню управления профилем в левом нижнем углу VS Code.

Выбрать:

```text
New Profile
```

Назвать профиль:

```text
LaTeX
```

В качестве основы можно выбрать:

```text
Empty Profile
```

Это создаст профиль без расширений и пользовательских настроек.

Так LaTeX-расширения и специфические настройки будут отделены, например, от профилей Python или обычного VS Code.

После создания выбрать профиль `LaTeX` для текущего окна.

VS Code связывает выбранный профиль с открытой папкой или workspace. В дальнейшем при открытии этой папки соответствующий профиль может активироваться автоматически.

---

## 3. Установка LaTeX Workshop

Находясь именно в профиле `LaTeX`, открыть Extensions:

```text
Ctrl+Shift+X
```

Найти:

```text
LaTeX Workshop
```

Расширение:

```text
LaTeX Workshop
Publisher: James Yu
```

и установить его.

Поскольку расширение устанавливается в профиль `LaTeX`, оно не обязано присутствовать в остальных профилях VS Code.

После установки при открытии `.tex`-файла VS Code должен распознавать язык как `LaTeX`.

---

## 4. Перенос длинных строк при отображении

В LaTeX исходный текст часто удобнее хранить в виде длинных логических строк и переносить их только визуально в редакторе.

Это **не изменяет содержимое `.tex`-файла** и не вставляет настоящие переводы строк.

Открыть настройки VS Code:

```text
Ctrl+,
```

Найти:

```text
Word Wrap
```

Для профиля LaTeX можно включить:

```text
Editor: Word Wrap → on
```

Если перенос нужен только для LaTeX-файлов, а не, например, для JSON или логов, лучше добавить language-specific настройку.

Открыть:

```text
Preferences: Open User Settings (JSON)
```

и добавить:

```json
"[latex]": {
    "editor.wordWrap": "on",
    "editor.wrappingIndent": "same"
}
```

Теперь длинные строки LaTeX будут визуально переноситься по ширине окна редактора.

При этом содержимое файла остаётся неизменным.

## 5. Проверка LaTeX из терминала

Открыть встроенный терминал VS Code:

```text
Ctrl+`
```

и проверить:

```powershell
pdflatex --version
```

Для MiKTeX также полезно проверить:

```powershell
latexmk --version
```

Если команды находятся, VS Code имеет доступ к LaTeX-инструментам через `PATH`.

Если `pdflatex` не находится, проблема находится не в LaTeX Workshop, а в установке LaTeX или системной переменной `PATH`.

---

## 6. Особенность MiKTeX: latexmk и Perl

LaTeX Workshop удобно использовать совместно с:

```text
latexmk
```

`latexmk` автоматически определяет, сколько раз нужно запустить LaTeX, BibTeX/Biber и другие инструменты.

Например, вместо ручной последовательности

```text
pdflatex
bibtex
pdflatex
pdflatex
```

обычно достаточно:

```powershell
latexmk article.tex
```

В MiKTeX `latexmk` требует Perl.

Проверить наличие Perl:

```powershell
perl --version
```

Если Perl отсутствует, можно:

* установить Perl;
* либо настроить LaTeX Workshop на сборку без `latexmk`.

Для больших статей с библиографией и несколькими файлами удобнее использовать `latexmk`.

## 7. Автоматическая сборка после изменения файлов

LaTeX Workshop может автоматически пересобирать проект после изменения его исходных файлов.

Для этого в настройках профиля `LaTeX` установить:

```json
"latex-workshop.latex.autoBuild.run": "onSave",
"latex-workshop.latex.autoBuild.onSave.files.ignore": [],
```

`onSave` означает, что LaTeX Workshop запускает сборку после сохранения изменений в файле проекта на диск.

Таким образом, обычная работа выглядит так:

```text
редактирование
      ↓
сохранение .tex
      ↓
LaTeX Workshop обнаруживает изменение
      ↓
latexmk
      ↓
новый PDF
      ↓
PDF viewer автоматически обновляется
```

### Изменения `.cls` и `.sty`

Для собственных классов и стилевых файлов требуется небольшая дополнительная настройка.

LaTeX Workshop определяет зависимости проекта по результатам предыдущей компиляции. При использовании `latexmk` создаётся `.fls`-файл, позволяющий расширению определить, какие `.cls`, `.sty` и другие файлы использует документ.

Поэтому сначала проект должен хотя бы один раз успешно собраться.

Есть ещё одна важная особенность: LaTeX Workshop по умолчанию исключает:

```text
**/*.sty
```

из файлов, отслеживаемых для `onSave`.

Чтобы изменение собственного `.sty` также запускало сборку:

1. открыть:

```text
Settings
```

2. найти:

```text
LaTeX Workshop › LaTeX › Watch › Files: Ignore
```

3. найти в списке:

```text
**/*.sty
```

4. удалить это исключение.

Остальные стандартные исключения лучше оставить.

После этого изменения зависимостей проекта будут обрабатываться следующим образом:

```text
*.tex ──┐
*.cls ──┼── изменение → автоматическая сборка
*.sty ──┘
```

при условии, что `.cls` или `.sty` действительно являются зависимостями текущего проекта.

Это особенно полезно при разработке собственных классов журналов, шаблонов и стилевых файлов.

## 8. Первая проверка

Создать файл:

```text
test.tex
```

с содержимым:

```latex
\documentclass{article}

\begin{document}

Hello, LaTeX!

\end{document}
```

Сохранить файл.

Для ручного запуска сборки:

```text
Ctrl+Alt+B
```

или открыть панель LaTeX Workshop и выбрать:

```text
Build LaTeX project
```

После успешной сборки должен появиться:

```text
test.pdf
```

После включения `onSave` последующие изменения и сохранения `test.tex` должны приводить к автоматической пересборке.

## 9. Проверка автоматической сборки `.sty`

Для проверки можно создать рядом с документом:

```text
test.sty
```

например:

```latex
\ProvidesPackage{test}

\newcommand{\testcommand}{First version}
```

В `test.tex`:

```latex
\documentclass{article}

\usepackage{test}

\begin{document}

\testcommand

\end{document}
```

Собрать проект один раз.

После этого изменить:

```latex
\newcommand{\testcommand}{Second version}
```

и сохранить `test.sty`.

Если `.sty` удалён из списка `latex-workshop.latex.watch.files.ignore`, LaTeX Workshop должен обнаружить изменение зависимости и автоматически пересобрать основной документ.

## 10. Просмотр PDF

LaTeX Workshop имеет встроенный PDF viewer.

Открыть скомпилированный PDF можно через панель LaTeX Workshop:

```text
View LaTeX PDF
```

PDF открывается непосредственно во вкладке VS Code.

Удобный вариант расположения:

```text
┌────────────────────┬────────────────────┐
│ article.tex        │ article.pdf        │
│                    │                    │
│ LaTeX source       │ PDF preview        │
│                    │                    │
└────────────────────┴────────────────────┘
```

После успешной автоматической сборки PDF viewer обновляет отображаемый документ.

---

## 11. SyncTeX

SyncTeX связывает положение текста в `.tex`-файле с соответствующим местом в PDF.

### Из исходного текста в PDF

Поставить курсор в нужное место `.tex` и использовать:

```text
Ctrl+Alt+J
```

LaTeX Workshop перейдёт к соответствующему месту PDF.

### Из PDF в исходный текст

Во встроенном PDF viewer:

```text
Ctrl + Click
```

по фрагменту документа.

VS Code перейдёт к соответствующей строке `.tex`.

Это особенно удобно при работе с большими статьями.

## 12. Структура реального проекта

Например:

```text
paper/
├── article.tex
├── references.bib
├── paper.cls
├── styles/
│   └── paper.sty
├── figures/
│   ├── figure1.pdf
│   └── figure2.pdf
├── sections/
│   ├── introduction.tex
│   └── discussion.tex
└── .vscode/
    └── settings.json
```

Основной файл:

```text
article.tex
```

может подключать остальные части через:

```latex
\input{sections/introduction}
```

или:

```latex
\include{sections/introduction}
```

LaTeX Workshop умеет определять основной root-файл и отслеживать зависимости многофайлового проекта.

## 13. Profile settings и project settings

Здесь полезно различать два уровня настроек.

### `.vscode/settings.json`

Настройки, относящиеся только к конкретной статье или проекту, лучше хранить в:

```text
.vscode/settings.json
```

Например, если проекту нужна нестандартная recipe, отдельный output directory или специальные параметры компилятора.

Таким образом:

```text
Profile LaTeX
    │
    ├── LaTeX Workshop
    ├── visual word wrap
    └── общая политика autobuild

Project/.vscode/settings.json
    │
    └── настройки конкретного проекта
```

Это позволяет не дублировать общую конфигурацию во всех LaTeX-репозиториях.

## 14. Git

В Git обычно следует сохранять исходные файлы:

```text
*.tex
*.bib
*.cls
*.sty
figures/
```

Настройки в:

```text
.vscode/settings.json
```

тоже можно хранить в Git, если они являются частью конфигурации конкретного проекта.

Временные файлы LaTeX лучше исключить через `.gitignore`.

Например:

```gitignore
*.aux
*.bbl
*.blg
*.fls
*.fdb_latexmk
*.log
*.out
*.synctex.gz
*.toc
```

Нужно отдельно решить, хранить ли PDF статьи в Git.

Для обычной разработки результирующий PDF часто является генерируемым файлом.

Но правило

```gitignore
*.pdf
```

не подходит, если в проекте находятся исходные PDF-рисунки.

В таком случае лучше исключать только конкретный результирующий файл:

```gitignore
/article.pdf
```

## 15. Что не стоит настраивать заранее

LaTeX Workshop имеет большое количество параметров:

* собственные tools;
* recipes;
* внешние PDF viewers;
* автоматическую очистку временных файлов;
* пользовательские команды;
* форматирование;
* linting;
* собственные сочетания клавиш.

Нет необходимости задавать всё это сразу.

Разумная конфигурация:

```text
VS Code profile LaTeX
        ↓
LaTeX Workshop
        ↓
latexmk
        ↓
MiKTeX / TeX Live
        ↓
PDF
```

с дополнительными удобствами:

```text
word wrap
automatic build
PDF preview
SyncTeX
```

## 16. Быстрая диагностика

Если документ не собирается, последовательно проверить:

```powershell
pdflatex --version
latexmk --version
perl --version
```

Затем попытаться выполнить сборку непосредственно из терминала:

```powershell
latexmk article.tex
```

Если команда не работает в терминале, сначала нужно исправить LaTeX/MiKTeX/Perl.

Если команда работает в терминале, но не работает в VS Code, тогда следует проверять LaTeX Workshop.

Если `.tex` автоматически пересобирается, а `.cls` или `.sty` нет:

1. убедиться, что проект хотя бы один раз успешно собран через `latexmk`;
2. проверить наличие `.fls`;
3. убедиться, что изменяемый `.cls` или `.sty` действительно используется проектом;
4. проверить:

```text
LaTeX Workshop › LaTeX › Watch › Files: Ignore
```

и убедиться, что:

```text
**/*.sty
```

не находится среди исключений.

Полезная модель для диагностики:

```text
LaTeX source
     ↓
LaTeX Workshop
     ↓
dependency watcher
     ↓
latexmk
     ↓
pdflatex / bibtex / biber
     ↓
MiKTeX / TeX Live
     ↓
PDF viewer
```
